## 1. Core Scientific Conceptual Distinctions

ZMIE enforces strict epistemological rigor by distinguishing three foundational concepts that are often conflated:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       REPRODUCIBILITY ≠ REPEATABILITY ≠ REPLICATION         │
├───────────────────┬─────────────────────────────────────────────────────────┤
│ Concept           │ Definition in ZMIE                                      │
├───────────────────┼─────────────────────────────────────────────────────────┤
│ Reproducibility   │ Same data + same analytical pipeline + same computation │
│                   │ yields the exact same numerical result.                 │
├───────────────────┼─────────────────────────────────────────────────────────┤
│ Repeatability     │ Same measurement procedure applied repeatedly under the │
│                   │ same conditions yields concordant results.              │
├───────────────────┼─────────────────────────────────────────────────────────┤
│ Replication       │ New study + new cohort/sample + independent analysis    │
│                   │ yields concordant scientific findings.                  │
└───────────────────┴─────────────────────────────────────────────────────────┘
```

## 2. The 13 Reproducibility Dimensions

Every research execution inside ZMIE tracks reproducibility guarantees across 13 explicit dimensions:

1. **Data Reproducibility**: Exact dataset snapshots, raw row hashes, and schema definitions.
2. **Source Reproducibility**: Retrieval timestamps, versioned source URLs, and database snapshots.
3. **Search Reproducibility**: Full normalized query strings, expansion terms, and applied filters.
4. **Terminology Reproducibility**: Concept mapping versions, ontologies, and transliteration tables.
5. **Code Reproducibility**: Exact Git repository commit hashes, script checksums, and package manifests.
6. **Environment Reproducibility**: OS version, Python/C runtime, CPU architecture, memory, and locked dependencies.
7. **Workflow Reproducibility**: Pipeline DAG IDs, task sequences, and step dependencies.
8. **Parameter Reproducibility**: Hyperparameters, priors, seeds, thresholds, and statistical cutoffs.
9. **Model Reproducibility**: Model weights, prompt templates, temperature, and architecture tags.
10. **Computational Reproducibility**: Numerical stability, floating-point precision, and deterministic execution flags.
11. **Statistical Reproducibility**: Estimators, formulas, variance algorithms, and confidence interval techniques.
12. **Result Reproducibility**: Effect sizes, p-values, odds ratios, and meta-analytic forest plot inputs.
13. **Interpretation Traceability**: Exact linkage from numeric results to claims and narrative conclusions.

## 3. Master Research Snapshots & Strict Immutability

### Immutability Guard
Once a `ResearchSnapshot` reaches publication-grade status:
- **In-place modifications are strictly prohibited.**
- Attempting to overwrite an existing locked snapshot raises a runtime `ValueError`.
- Any corrections, new evidence, or re-analyses must derive a child snapshot (`create_child_snapshot`) with an incremented semantic version (e.g., `1.0.0` $\rightarrow$ `1.1.0`), recording the exact parent-child provenance link.

### Machine-Readable Manifest
Every snapshot automatically computes a deterministic SHA256 integrity hash across its components and provides an exportable manifest:
```json
{
  "snapshot_id": "rs-golden-berberine-01",
  "version": "1.0.0",
  "parent_snapshot_id": null,
  "sources_count": 2,
  "evidence_count": 1,
  "extractions_count": 1,
  "workflow_id": "wf-meta-synthesis-v1",
  "manifest_hash": "sha256:67a3218a5e90d486e9588ba75df0fa9b20bb42026ed822d751fbf3353fef42e7",
  "timestamp": "2026-10-04T00:20:40.756690"
}
```

## 4. Cryptographic SHA256 Hash-Chained Audit Trail

Audit events form an append-only, tamper-evident hash chain:
$$H_i = \text{SHA256}(\text{event\_id}_i : \text{audit\_id} : \text{action}_i : \text{resource\_id}_i : H_{i-1})$$
where $H_0 = \text{"GENESIS\_EVENT"}$.

### Verification & Red-Team Tamper Detection
- `verify_chain(audit_id)` traverses the chain from genesis to head.
- Any event insertion, deletion, reordering, or byte-level modification breaks the chain hash link and is flagged immediately as `EVENT_HASH_MUTATED` or `CHAIN_BROKEN_PREVIOUS_HASH_MISMATCH`.

## 5. Bidirectional Provenance Graph (DAG)

ZMIE maintains full execution traces representing the complete research lifecycle:

```text
Question ──> Plan ──> Search ──> Sources ──> Studies ──> Screening ──> Extraction
                                                                            │
Conclusion <── Review <── Claim <── Result <── Model <── Analysis <── Data ─┘
```

- **Backward Attribution (`backward_trace`)**: Given a conclusion, traverses upstream through supporting claims and results back to raw extractions, studies, and search strategies.
- **Forward Impact Analysis (`forward_trace`)**: Given a retracted or disputed study, traverses downstream to pinpoint every affected analysis, result, claim, and conclusion across the knowledge graph.

---

## 6. Systematic Screening & Double-Extraction Reconciliation

- **Standardized Exclusion Reasons**: In accordance with PRISMA guidelines, study exclusion requires an explicit `ExclusionReason` (`WRONG_POPULATION`, `WRONG_INTERVENTION`, `WRONG_COMPARATOR`, `WRONG_OUTCOME`, `WRONG_STUDY_DESIGN`, `DUPLICATE`, etc.). Arbitrary exclusion is rejected at the API boundary.
- **Double-Blind Extraction**: Independent extraction by two reviewers (human or agent). Concordant fields are approved automatically; discrepancies create an `ExtractionDisagreement` tracking reviewer values and requiring documented consensus adjudication.

---

## 7. Scientific Integrity & Zero-Fabrication Gates

1. **Zero-Fabrication Citation Check**: All citations in claims and conclusions are resolved against verified sources and studies. Phantom or hallucinated citations are flagged as `CRITICAL` severity findings.
2. **Causal Language Audit**: Detects unjustified deterministic causal statements (`"proves"`, `"cures"`, `"eradicates"`) in observational studies, requiring counterfactual DAG backing or hedging.
3. **Pre-Registration Deviation Tracking**: Compares executed models against pre-registered analysis plans (`AnalysisPlanRecord`), flagging changed endpoints or post-hoc subgroup splits.
4. **Numeric Integrity Audit**: Validates that numeric claims correspond within tolerance to computed analytical outputs.

## 8. Sandbox Reproduction Engine & Comparison Matrix

Reproduction runs (`ReproductionRun`) execute in an isolated sandbox (`ReproductionMode.SANDBOX`), generating a 5-stage comparison matrix:

| Stage | Original Baseline | Reproduced Re-execution | Difference | Acceptable |
| :--- | :--- | :--- | :--- | :--- |
| **Search** | 42 studies | 42 studies | NONE | True |
| **Data** | 1 items, 1 extractions | 1 items, 1 extractions | NONE | True |
| **Analysis** | `wf-meta-synthesis-v1` | `wf-meta-synthesis-v1` | NONE | True |
| **Computation** | SUCCESS (Seed 42) | SUCCESS | NONE | True |
| **Result** | 1 metrics computed | 1 metrics computed | NONE | True |

### Outcome States
- `REPRODUCED`: Exact match across all stages.
- `PARTIALLY_REPRODUCED`: Minor acceptable variance (e.g., source transiently unavailable or non-critical precision divergence).
- `NOT_REPRODUCIBLE`: Fundamental computation failure or result conflict.

## 9. Official Scientific Certificates & Research Audit Packets

- **`ZMIEReproducibilityCertificate`**: Certifies locks across all 13 reproducibility dimensions, deterministic seeds, and code/data SHA256 hashes.
- **`ZMIEResearchAuditCertificate`**: Certifies provenance completeness (100%), cryptographic chain validity, and board review sign-off.
- **`ResearchAuditPacket`**: Comprehensive machine-readable and executive document bundling manifests, methodologies, findings, and certificates (exportable in JSON or HTML).

## 10. Tenant Isolation, Legal Holds & Auditor View Redaction

- **Tenant Isolation**: Workspaces and audit logs are partitioned by `tenant_id`. Cross-tenant audit inspection returns `404 / 403`.
- **Auditor View vs Raw Data View**: Auditors without PHI/row-level permissions receive masked dataset structures (`REDACTED_FOR_AUDIT_VIEW`), allowing complete methodological inspection without privacy leaks.
- **Legal & Regulatory Preservation Hold**: When `is_held = True`, deletion, purging, or superseding is strictly prevented.

## 12. Python SDK Usage

```python
from zmie.client import ZMIE

client = ZMIE(base_url="http://localhost:8000", api_key="zmie_live_...")

# 1. Inspect immutable snapshot & manifest
snapshot = client.audit.snapshots.get("rs-golden-berberine-01", include_raw_data=False)
manifest = client.audit.snapshots.manifest("rs-golden-berberine-01")

# 2. Verify tamper-free cryptographic hash chain
verification = client.audit.verify_chain("audit-golden-berberine-01")
assert verification["is_valid"] is True

# 3. Traverse bidirectional provenance trace
trace = client.audit.provenance.get_trace("rs-golden-berberine-01")
backward_path = client.audit.provenance.backward("rs-golden-berberine-01", node_id="node-concl-01")

# 4. Execute controlled sandbox reproduction
reproduction = client.audit.reproduce.run("rs-golden-berberine-01", mode="SANDBOX")
print("Reproduction Status:", reproduction["status"])  # REPRODUCED

# 5. Issue certificates and export audit packet
certificates = client.audit.certificates.issue("audit-golden-berberine-01")
packet_json = client.audit.certificates.packet("audit-golden-berberine-01", format="json")
packet_html = client.audit.certificates.packet("audit-golden-berberine-01", format="html")

# 6. Derive child snapshot and compute scientific answer diff
child = client.audit.snapshots.create_child(
    parent_snapshot_id="rs-golden-berberine-01",
    updates={"final_output": {"conclusion": "Updated synthesis with new RCT."}}
)
diff = client.audit.diff(old_snapshot_id="rs-golden-berberine-01", new_snapshot_id=child["snapshot_id"])
```
